# 실시간 시세 REST 폴백 최적화: 2026-08-27

## 발견한 문제

Toss WebSocket이 정상 연결되어 실시간 시세를 받고 있어도 프론트가 같은 종목의 REST 현재가를 5초마다
계속 요청했다. 화면은 정상처럼 보이지만 공급자 호출량과 서버 로그가 불필요하게 증가하는 문제였다.
초기 REST 요청이 실패한 뒤 WebSocket 시세가 정상 도착해도 REST 오류 경고가 남을 수 있었다.

## 수정

- 실시간 상태가 `live`이면 REST 현재가의 주기적 재조회는 중단한다.
- 브라우저가 `offline`일 때도 실패할 REST 요청을 반복하지 않는다.
- 실시간 연결 준비·재연결·사용 불가 상태에서는 5초 REST 폴백을 유지한다.
- WebSocket 시세가 있으면 이전 REST 요청의 오류 경고를 표시하지 않는다.

초기 REST 조회는 그대로 유지하므로 WebSocket 첫 메시지를 기다리는 동안에도 가격을 보여줄 수 있다.

## 검증

- TypeScript 검사 통과
- 프론트 단위 테스트 19개 통과
- 실제 Toss WebSocket이 `live`가 된 뒤 6.5초 동안 REST 현재가 추가 요청 0건
- Playwright 전체 실행: 17개 통과, 화면별 조건 테스트 19개 제외, 실패 0개
- Next.js 운영 빌드와 Docker 웹 컨테이너 재기동 성공

이 검증은 API 호출량을 줄이는 동작만 확인하며 공급자의 요금제나 일일 제한 자체를 보장하지 않는다.
