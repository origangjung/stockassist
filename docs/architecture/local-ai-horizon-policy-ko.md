# 전문 AI별 예측 기간 정책

## 왜 하나의 5일 정답을 쓰지 않는가

각 전문 AI가 보는 정보의 유효 기간이 다르다. 뉴스 충격은 보통 빠르게 가격에 반영되지만,
분기 재무 변화는 더 긴 기간에 걸쳐 평가된다. 서로 다른 질문을 모두 "5거래일 뒤 SPY보다
올랐는가"로 바꾸면 재무 AI가 단기 뉴스 잡음을 학습하고, 종합 단계에서는 의미가 다른 확률이
섞인다.

현재 정책은 다음과 같다.

| 전문 AI | 기본 기간 | 학습 정답 |
|---|---:|---|
| 기술 | 10거래일 | 시장 대비 가격 흐름의 방향 |
| 재무 | 20거래일 | 공개된 재무 변화 이후 시장의 재평가 방향 |
| 뉴스 | 3거래일 | 공개 이벤트 직후 시장 대비 가격 반응 |
| 수급 | 10거래일 | 매수·매도 흐름의 지속 방향 |
| 위험 | 5거래일 | 가까운 기간의 하락 사건 발생 여부 |

기존 모델을 읽기 위해 일부 역할은 과거 5일 artifact를 호환하지만, 새 수집의 기본값으로
사용하지 않는다.

## 데이터 수집과 라벨링

시세는 한 번 받아 기술 10일, 위험 5일, 재무 라벨용 20일 결과를 함께 계산한다. 뉴스는
기사 공개 시점부터 3일 반응을 자체 계산하고, FINRA 수급은 10일 결과를 자체 계산한다.
따라서 뉴스와 수급 데이터를 공통 5일 정답으로 다시 덮어쓰지 않는다.

뉴스 입력은 NewsAPI/GDELT와 함께 SEC·연준·Apple이 공식 배포하는 RSS 메타데이터를 사용할 수
있다. RSS 수집기는 기사 본문을 저장하지 않으며 공식 원문 링크, 제목, 출처와 시각만 보존한다.

예전 CSV에 `horizon_days` 열이 없으면 5일 자료로 간주한다. 새 기간으로 수집할 때 기존 파일은
`*-legacy-5d.csv`로 보관하고 새 파일을 시작한다. 과거 행의 기간 숫자만 바꾸는 행위는 금지한다.

## 검증과 운영 표시

- CSV에는 `horizon_days`가 정확히 하나만 있어야 한다.
- 역할에 허용되지 않은 기간은 후보 검증 전에 거절한다.
- 시간순 중첩 검증의 purge 간격은 해당 데이터 기간을 따른다.
- 모델 JSON과 모델 버전 해시에는 예측 기간을 기록한다.
- API 결과는 `horizon_days`와 기간이 포함된 `target`을 반환한다.
- 종합 결과는 하나의 상승 확률이 아니라, 서로 다른 기간의 전문 신호를 모은 진단 점수다.
- 후보가 통과해도 자동 승격하지 않고 기존 운영 모델과 별도로 보관한다.

## 실행

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\operations\run_local_ai_collection.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\operations\run_local_ai_candidate_validation.ps1
```

첫 실행에서는 뉴스 3일·수급 10일 데이터가 새로 시작되므로 당분간 `collect_more_data`가 정상이다.
기존 5일 운영 모델은 새 후보가 시간순 검증을 통과하고 수동 승인되기 전까지 그대로 유지된다.
